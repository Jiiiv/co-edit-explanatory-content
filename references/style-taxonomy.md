# 叙事模式分类与自动选择

风格不是固定模板，也不是五十五篇文章各自独立的腔调。根据现有逐篇研究，将可迁移的写法归为六类叙事模式，再用八个维度描述每篇的组合。每次创作选择一个主模式和至多一个辅助模式，避免平均混合成无辨识度的综合腔。

## 编辑版说明

本文件在编辑版中不再是后台自动选择表。模式判断由编辑做出，并且**说出来**：编辑在开题和改稿时明确报出主模式、辅助模式和选择理由，让用户有机会当场否决，而不是稿子写完才暴露方向错误。下面六类模式的名称和结构沿用原 Skill，八维度、样本调用与漂移检查的执行方式按编辑动作改写。

## 六类叙事模式

1. **宏大叙事切现实**：熟悉的时代、行业或公共叙事 → 现实错位 → 具体案例 → 追问原因。适合行业乱象、商业模式和技术泡沫。
2. **反常结果追因**：不合理结果 → 观众疑问 → 倒叙背景 → 条件变化 → 结果形成。适合“功能存在但结果缺失”等题材。
3. **物件或系统追踪**：一个物件、资金、制度或工具贯穿多个环节，每次出现都改变含义，最后回收。适合产业链、交易和风险转移。
4. **人物关系与利益变化**：人物目标 → 依赖与交换 → 行动改变选择空间 → 条件变化 → 谁获益、谁承担后果。适合组织和合作关系。
5. **机制拆解与反例推进**：常见解释 → 反例 → 解释失效处 → 更精确模型 → 模型边界。适合技术、科研和认知纠偏。
6. **历史回望与条件变化**：今天的疑问 → 回到过去 → 当时为何合理 → 条件如何改变 → 今天的约束。适合历史、制度和行业演变。

## 八个描述维度

- 入口：宏观引申、反常结果、历史回望、具体场景或人物。
- 主线对象：人物、物件、资金、制度、空间或技术。
- 推进：追因、排除、比较、递进、资金流动或回环。
- 揭示速度：判断前置、逐层揭示或延迟揭示。
- 声线：新闻、解释、评论、讽刺、对白和假设的组合。
- 材料密度：事实、机制、人物关系或场景动作占比。
- 判断力度：谨慎、明确、尖锐或讽刺；不得超过证据。
- 结尾：回收对象、回到人物、落到代价、开放问题或判断方法。

八个维度也是编辑向用户解释选择理由时使用的语言，不要退化成内部标签。

## 模式的判断与报出

编辑在开题和改稿时说出自己的模式选择及理由，例如“这期我建议用物件追踪，因为你会销那笔代理费贯穿了四个环节，每次出现含义都不一样”。判断依据来自当前材料：最强矛盾是什么、是否有可追踪对象、宏观判断与具体动作哪一方更有承重力、是否需要倒叙、哪种声线能完成解释。输出不再是后台静默记录，而是一句可以直接被用户否决的话。

用户提出结构时，编辑先判断它是什么模式，再判断它是否比编辑自己的选择更好。如果用户提的结构其实更适合另一种模式，编辑要直接指出来并给出替代：“你现在的搭法更接近机制拆解，但如果主线是那笔代理费，物件追踪会更容易在结尾回收。”替代方案必须落在材料上，不能只是换一个更好听的说法。

每次创作选择一个主模式和至多一个辅助模式，避免平均混合成无辨识度的综合腔。编辑负责守住这条线：发现稿子在混搭时，明确要求收敛到一种主模式，并指出哪几段属于另一种模式、需要合并、删除还是挪到下一期。

如果当前项目是AI商业化题材，默认候选是：宏大叙事切现实为主，物件或系统追踪为辅；“代理资格”或“一笔代理费”作为主线对象，必要时切入反常结果追因。这是条件式的默认值，不是本 Skill 的绑定题材：其他题材按同一套判断重新选择。材料不足时不得强行套用，改为短试写或继续对谈。

## 样本调用

完整文章用于建库时理解模式协同；骨架笔记用于确定主模式；功能片段只在某个具体位置卡住时调用一条；失败对照每次生成前优先读取一条相近案例。编辑写新段前先按[风格样本库与同步协议](style-library-protocol.md)的调用规则读取一条最相近的失败对照，用它预判这一稿可能犯什么错。不得同时加载多个互相竞争的风格模板。

## 漂移检查

短试段和长篇扩写后，检查入口是否被改写、主线对象是否消失、推进方式是否改变、声线是否无触发切换、结尾是否仍能回收。发现漂移时编辑不只标记，而是回到最近一个稳定段落重写，从那里恢复模式再往下走；不继续向后补段，也不把漂移段落单独润色后放回原位。重写范围涉及主线对象或推进方式时，按[编辑运行协议](editorial-protocol.md)的下场改稿规则，向用户说明改了哪几处以及为什么。
